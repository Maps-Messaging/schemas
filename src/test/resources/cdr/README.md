# CDR interoperability fixtures

These fixtures contain **independently sourced XCDR1 plain CDR** byte streams. They are deliberately
not generated by MapsMessaging's own `CdrWriter`; tests compare both decoding and exact re-encoding.
All fixture data here is under **Apache License 2.0**, and attribution to its respective upstream
project is retained. The repository root `LICENSE` includes the Apache 2.0 terms.

## ROS 2 rosbag2 recording

Upstream: [ros2/rosbag2](https://github.com/ros2/rosbag2)

- Pinned upstream commit: `c73ae2d4ccdaead6e520aaa9f8079287825a7764`
- Original SQLite database:
  `rosbag2_tests/resources/sqlite3/cdr_test/cdr_test_0.db3`
- Upstream Git blob SHA-1: `d24e8d84e2da6606b66ec197013850c4e3540a30`
- Original metadata:
  `rosbag2_tests/resources/sqlite3/cdr_test/metadata.yaml`
- License: [Apache License 2.0](https://github.com/ros2/rosbag2/blob/c73ae2d4ccdaead6e520aaa9f8079287825a7764/LICENSE)
- Data attribution: ROS 2/rosbag2 contributors.

The upstream recording has **3 BasicTypes** and **4 Arrays** serialized CDR messages.
The stored database contains duplicate payloads of each kind; these fixtures retain one
representative payload of each kind.

- `ros2/basic-types.hex`: **52 bytes**, unmodified full `test_msgs/msg/BasicTypes` payload
  from row 1 of SQLite table `messages`. `int32_value` is 123; remaining values are zero/false.
- `ros2/basic-types.schema.json` and `ros2/basic-types.expected.json`: matching canonical CDR
  field description and expected decoded values.
- `ros2/arrays-original-full.hex`: **696 bytes**, full, unmodified `test_msgs/msg/Arrays`
  payload from row 2 of SQLite table `messages`.
- `ros2/arrays-primitives.hex`: **148 bytes**, exact first 148 bytes (including CDR encapsulation)
  of that recorded Arrays payload. It ends after the original message's first 13 fixed arrays:
  boolean, byte, char, float32, float64, int8, uint8, int16, uint16, int32, uint32, int64, uint64.
- `ros2/arrays-primitives.schema.json` and `ros2/arrays-primitives.expected.json`: the matching
  ordered canonical fields and expected values for that prefix.

The `Arrays` prefix is **derived by slicing an external recording**, not by running
our encoder. The original full payload is retained to verify that the prefix has not
been altered. The 696-byte message also has strings, nested ROS-specific messages
and defaults beyond the present partial fixture definition. Do not treat
`arrays-primitives.hex` as an original complete ROS message or attempt to decode
the full 696 bytes using its schema.

Hex files contain whitespace-separated hexadecimal bytes; tests remove whitespace
and decode them using Java 17 `HexFormat`.

## eProsima Fast-CDR golden vectors

Upstream: [eProsima/Fast-CDR](https://github.com/eProsima/Fast-CDR)

- Pinned upstream commit: `0e2650a58c1968ca2acc3314e17ed2f8a1188f93`
- Original source: `test/cdr/array_as_std_vector.cpp`
- License: [Apache License 2.0](https://github.com/eProsima/Fast-CDR/blob/0e2650a58c1968ca2acc3314e17ed2f8a1188f93/LICENSE)
- Data attribution: eProsima / Proyectos y Sistemas de Mantenimiento SL.
- Fixture: `fastcdr/verified-xcdr1-vectors.json`

The file retains the upstream C++ tests' exact **PLAIN_CDR** expected octets for
big- and little-endian streams, along with their known values and a matching
canonical CDR schema. It covers a fixed uint32 array, boolean array and array
of two nested structures containing uint16 fields. Values such as `ival = 0xCD`
and `fval = 0xDC` are substituted into the original upstream literal expected
streams; these are transcriptions of upstream golden bytes, **not independently
executed C++ output**.

Fast-CDR also has XCDR2 and parameter-list vectors in these files. They have
not been copied into the executable plain-XCDR1 tests because those formats
are outside the current formatter's supported subset.

## Validation

`TestCdrRecordedFixtures` compares real ROS 2 samples with their expected
JSON and tests byte-exact re-encoding. `TestCdrFastCdrFixtures` compares six
independent upstream reference streams (three cases × two endian modes).
Truncation and incompatible/full-message cases are also checked.

Adding new fixtures: pin an upstream commit; retain the original URL, license,
byte-exact payload, source type definition, and expected decoded fields.
Do not generate "golden" data using the MapsMessaging CDR codec.
